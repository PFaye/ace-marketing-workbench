# ACE 营销工作台 · 作品说明与面试演示

**一句话：** 一个用 AI 搭建、由 AI 驱动、能在真实业务里跑起来的营销执行工具。把 agency 每天在做的六件事（出全案、批量写稿、看评论、选达人、盯投放、搬数据）串成一条流程，AI 负责生成与判断，公式负责可解释的计算，人负责确认。

作品链接：
- 自托管版（国内可打开，评委无需登录即可试用生成）：https://ace-marketing-workbench-production.up.railway.app
- Claude 原生版：https://claude.ai/artifact/PwZEWZ4o8AWVU4kta2M8Gv

示例品牌「泡研社」、12 位达人、14 天投放数据、30 条评论均为虚构演示数据，页面已标明。作品不代表任何公司的官方产品或真实客户成果。

## 要解决的具体问题

| 工作里的问题 | 作品里的做法 | 交出去的东西 |
|---|---|---|
| 接到 Brief 要很快拿出有洞察、能落地的全案 | 五个智能体接力：洞察 → 策略 → 内容 → 媒介 → 执行指令，结构化 JSON 输出 | 一份可复制的 Markdown 全案 |
| 铺量期要几十条不重样、审过才能交付的稿件 | 多视角流式批量生成；逐条改稿、标记审校；广告法敏感词自动提示 | 带审校状态的 CSV |
| 评论区几百条声音没人看，负面发酵了才知道 | 粘贴评论 → 主题 / 原话 / 情绪 / 建议动作，标出需立刻回应的负面 | 洞察报告 |
| 达人名单几十上百个，筛选靠人肉看数据 | 导入名单自动识别字段；CPM / CPE / 互动率按公式算；预算组合；AI 评估；合作状态与跟进日 | 达人库 CSV、合作 Brief |
| 投放数据每天看后台，异常靠人盯 | 导入日报 → 规则告警（CTR 跌、CPA 超、负评涨）→ AI 日报 → 定时推飞书 / 企微群 | 群里每天一条日报 |
| 数据散在各平台，重复搬运 | 表格导入自动映射；HTTP 接口定时拉取；官方广告 API 接入层预留 | 统一的数据底座 |

## 三分钟演示

**整体操作只有三类动作：粘贴、点一下、拖进来。** 全案是把 Brief 粘进去；内容、日报、达人组合都是一个按钮；换数据是把表格拖进来。

**00:00–00:20 开场。** “这是我做的营销工作台。不是让 AI 写文案，而是把 agency 每天的六件事串起来，每一步都能交付。先看它最像日常工作的部分：盯投放。”

**00:20–01:00 投放监测。** 打开「投放监测」：“数据是导入的投放日报。昨天程序化广告 CTR 掉到 0.9%，抖音负评 24 条，规则自动打了告警。点「运行监测」，AI 写出日报并推到飞书群。规则是透明的，CPA 超过 35 元告警，阈值我自己定。”

**01:00–01:40 内容工厂。** “铺量期一次要几十条稿。选视角、数量，开始生成，稿件一条条出来。每条有审校状态，敏感词会标出来，改完稿自动回到待审校。只导出审过的。这是品牌官方和合作达人的参考稿，不是水军。”

**01:40–02:20 达人匹配。** “蒲公英没有公开 API，名单只能导出。把表格拖进「数据接入」，字段自动识别。回到达人库，CPM、CPE 按公式算，按预算自动选组合，AI 给评估意见，状态和跟进日在这里管。选好人，一键生成合作 Brief。”

**02:20–02:45 全案与洞察。** “接到新 Brief，五个智能体接力出全案，结果作为当前项目，其他工具都引用它。评论洞察把几百条评论归纳成主题和原话，负面单独列出来。”

**02:45–03:00 边界与下一步。** “AI 生成的都标注来源，公式计算的都能复核，KPI 是区间估算不是承诺。官方广告 API 需要企业资质，接入层已经留好，进了公司配上凭证就能用。”

## 网申作品描述（150 字）

ACE营销工作台是用AI辅助构建、由AI驱动的营销执行工具，面向agency日常交付：五个智能体接力生成从消费者洞察到执行指令的全案；批量生成多视角稿件并支持逐条审校、敏感词提示与CSV交付；导入达人名单自动识别字段，按公式算性价比、按预算组合、AI评估并管理合作跟进；导入投放日报后按规则告警，AI日报定时推送飞书/企微群。前端单页，后端Node，支持DeepSeek等国内模型。

## 技术与设计说明

- **多智能体接力，结构化输出。** 每个智能体只负责一个环节，返回约定格式的 JSON，页面渲染为卡片、表格、图表。内容工厂逐行流式输出，稿件一条条出现。
- **模型可替换。** Claude 环境中直接调用 Claude；自行部署时后端统一代理 DeepSeek / Kimi / 通义千问 / Anthropic，Key 不出服务端。访客试用有每日次数上限。
- **可解释的部分不用 AI。** CPM / CPE / 互动率、预算组合、告警规则都是公开公式，能复核；AI 负责判断与写作。
- **合规内置。** 广告法绝对化用语、酒类广告边界、AIGC 标识义务、反不正当竞争法对刷评的禁止写进了生成规则与审校提示。
- **数据边界诚实。** 蒲公英无公开 API，走表格导入；巨量引擎 / 聚光官方 API 需企业资质，接入层预留；示例数据均为虚构。

## 我负责的部分

产品定义（六个工具分别解决什么问题、输入输出是什么）、每个智能体的提示词与输出结构、审校与合规规则、交互与界面质量把控、测试与部署。代码由 Claude Code 在我的指令下实现。面试前请至少亲自完成一次：导入一份表格、生成一批稿件并审校导出、运行一次监测并推送到自己的测试群。

## 局限

KPI 与达人评分是估算与判断，不是效果预测；官方广告平台的拉取逻辑需拿到企业凭证后按官方文档补全；未在真实项目中测量节省的工时。
