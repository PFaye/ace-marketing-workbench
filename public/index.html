作品说明

这是什么，怎么搭的，为什么这样设计

ACE 营销工作台是我为「AI 营销 ACE」校招岗位搭建的作品：一个用 AI 搭建、也由 AI 驱动、能在真实业务里跑起来的营销执行工具。它不做泛泛的"AI 写文案"，而是围绕 agency 每天要解决的具体问题，把 AI 生成、人工审校、数据接入和日常监测串成一条流程。

六个工具，对应六类日常问题

接到 Brief，要在很短时间里拿出有洞察、能落地的全案→全案策划：五个智能体接力，从消费者洞察到给技术中台的执行指令
铺量期需要几十条不重样的稿件，而且得审过才能交付→内容工厂：批量生成、逐条审校改稿、敏感词提示、只导出已审校
评论区几百条声音没人看，负面发酵了才知道→评论洞察：主题归纳、原话引用、负面预警、内容机会
达人名单几十上百个，筛选靠人肉看数据→达人匹配：导入名单、公式算性价比、预算组合、AI 评估、合作跟进
投放数据每天看后台，异常靠人盯→投放监测：规则告警、AI 日报、定时推送到飞书 / 企微群
数据散在各平台后台，重复搬运→数据接入：表格自动识别字段，定时接口，官方平台接入层预留

怎么工作的

  • 多智能体接力，结构化输出。每个智能体只负责一个专业环节，返回约定格式的 JSON，页面渲染成卡片、表格和图表；内容工厂用逐行流式输出，稿件一条条出现。
  • 模型可替换。在 Claude 环境中直接调用 Claude；自行部署时后端统一代理 DeepSeek、Kimi、通义千问或 Anthropic 接口，Key 不出服务端。
  • 能落地的部分不靠 AI。CPM / CPE / 互动率、预算组合、告警规则都是公开公式，可解释、可复核；AI 负责判断与写作，人负责确认。
  • 合规内置。广告法绝对化用语、酒类广告边界、AIGC 标识义务、反不正当竞争法对刷评的禁止，都写进了生成规则与审校提示。
  • 数据边界诚实。蒲公英没有公开 API，达人数据走表格导入；官方广告 API 需企业资质，接入层预留；示例数据均为虚构，页面会标明。

我是怎么搭的

整个工具通过与 Claude Code 对话完成：我定义产品逻辑（每个工具解决什么问题、输入输出是什么）、设计智能体提示词与输出结构、把控文案与界面质量；AI 负责实现为可部署的 Web 应用（前端单页 + Node 后端）。这正是我理解的 AI 营销 ACE 的工作方式：人定义问题与标准，AI 放大执行。

先看一个案例演示？

导入一份达人名单和投放日报，再用一段 Brief 一键生成方案、稿件、达人组合。全程自动，约 1-2 分钟。

完整流程

五步，每步一个动作

1定项目。粘 Brief → 生成。要改就在「项目设定」改，不用上传。
2出内容。选类型和数量 → 生成 → 审校 → 导出。
3选达人。表格拖进「数据接入」→「达人匹配」一键选人 → 生成 Brief。
4盯投放。每天拖日报表进来 → 自动告警 → 日报推群。
5看反馈。粘评论 → 分析。

常见问题

  • 改方案要重新上传吗？不用，改「项目设定」就行。
  • 上传表格会影响方案吗？不会，互不影响。
  • 换客户？粘新 Brief 生成即可。
  • 数据存在哪？部署版在服务端，本地版在浏览器。
